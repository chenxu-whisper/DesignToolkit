# Studio Chroma Keyer MVP PRD

## 1. 产品定位

Studio Chroma Keyer 是 DesignToolkit 中的本地专业抠像模块。它使用公开图像处理原理生成连续 Alpha Matte，不使用任何第三方私有抠像算法。

本阶段解决单张图片或单个视频中具有一个明确主导 RGB 通道的纯色幕背景抠除
问题，典型场景为绿幕、蓝幕或红幕：用户在画布上吸取当前画面的实际幕色，
调整基础参数，预览并导出透明 PNG 或完整 PNG 序列。青色、黄色、品红色等
双通道共同主导的颜色以及中性色按设计拒绝；MVP 不支持通用的任意纯色背景。

## 2. MVP 目标

1. 从本机绝对路径导入一张 PNG、JPG、JPEG 图片，或一个 FFmpeg 可解码的
   MOV、MP4、M4V、WebM、MKV、AVI 视频。
2. 展示缩放预览画布；视频同时展示时间轴和元数据，并允许查看、定位当前帧。
3. 允许用户在当前图片或视频帧上吸取一个待抠除的背景颜色；再次吸取时替换当前颜色。
4. 基于采样颜色生成连续 Alpha Matte，不要求用户预先选择“绿幕”或“蓝幕”。
5. 支持基础 Matte 调整、边缘羽化及基于采样背景色反混合的 Despill。
6. 支持当前图片或当前视频帧的 Final 和 Alpha Matte 预览。
7. 图片导出原图分辨率 RGBA PNG；视频按原始解码帧率完整导出原尺寸 RGBA PNG 序列。

## 3. 非目标

MVP 不实现以下能力：

- 浏览器文件上传、拖入上传、云端或对象存储。
- 图片序列或 ZIP 导入，以及图片或视频批量抠像。
- 音频处理或保留、参数关键帧、入点/出点范围导出或取消任务。
- GPU/WebGL 实时计算、AI 边缘恢复、Guided Filter、ProRes 或 EXR 输出。
- 自动背景颜色检测、前景/背景画笔或 Trimap。

视频 v1 对整个视频使用同一个 Screen Color 和同一组静态七参数，不提供逐帧或
关键帧参数变化。

## 4. 用户流程

1. 用户进入“Studio Chroma Keyer”模块。
2. 用户通过路径输入框或文件夹按钮选择一张本地图片或一个本地视频；路径经
   Enter、失焦、原生选择器、拖放解析或路径编辑器确认后自动加载，不提供额外的
   “加载图片/视频”按钮。
3. 图片检查返回预览和原图尺寸；视频检查解码首帧并返回预览、源尺寸、帧率、
   时长和估算帧数，界面显示时间轴。
4. 视频用户可拖动时间轴；系统以最新选择的时间戳为准加载当前帧，过期响应不得
   覆盖更新后的画面。
5. 用户启用取样工具，在当前预览画布点击背景区域。
6. 前端将预览坐标、预览尺寸以及视频当前帧时间戳提交给后端；后端从原图或指定
   解码帧换算源坐标并返回采样颜色。
7. 用户可重新取样以替换当前颜色，或清空当前颜色。
8. 取得一个有效采样色后，系统生成预览；用户通过同步的滑块和数值输入框调整参数。
9. 有效参数变化经过 `150 ms` 防抖后请求当前图片或视频帧预览，期间的新变化替换待发请求；
   用户在 Final / Alpha Matte 视图中检查结果。
10. 图片用户选择输出文件；视频用户选择输出根目录。系统创建异步任务并展示逐帧
    进度、完成状态和最终输出位置。

## 5. 本地路径约束

本项目的 Web GUI 运行在本地，浏览器不能可靠地取得绝对文件路径。MVP 必须沿用现有模式：

- 用户可手动粘贴本地绝对路径。
- 文件夹图标调用 FastAPI 进程提供的本机原生文件选择器。
- 手动路径仅在 Enter 或失焦时确认；原生选择、拖放解析和路径编辑器应用会直接确认。
- 已确认路径按后缀自动触发图片或视频检查，不提供独立的“加载”按钮。
- 不提供 multipart 上传端点。
- 仅处理当前 FastAPI 进程可访问的本地文件。

## 6. 采样与颜色模型

### 6.1 颜色吸取

- 用户吸取的是“需要被抠除的实际背景颜色”，该颜色必须有一个明确主导的 RGB
  通道，例如典型的绿色、蓝色或红色幕布。
- 青色、黄色、品红色等双通道共同主导的颜色以及灰色、白色、黑色等中性色
  按设计拒绝，而不是作为通用纯色背景处理。
- 系统只保留一个采样颜色；再次点击画布时，新颜色替换原颜色。视频在当前已渲染
  帧取样，并在整段视频导出中保持该 Screen Color 不变。
- UI 显示当前采样色块、RGB 和 HEX，并支持清空。
- 预览和导出请求必须包含且仅包含一个采样颜色；清空后不可预览或导出。
- 采样色的最强通道必须比其余通道至少高 `12.75`，否则按低饱和度背景拒绝，并提示用户选择具有明显主色的纯色幕背景。

### 6.2 坐标契约

前端请求包含 `x`、`y`、`preview_width`、`preview_height`。后端按下式映射并截断到原图边界：

```text
source_x = floor(x * source_width / preview_width)
source_y = floor(y * source_height / preview_height)
```

采样必须来自原图，而非浏览器缩放、压缩或叠加后的像素。

### 6.3 单色模型

`screen_model_from_samples` 严格接收一个 RGB 采样值。`mean_rgb` 等于该采样值，
`stddev_rgb` 固定为零，`samples` 只包含该颜色。空列表、多于一个颜色或低饱和度
颜色均拒绝，不再通过多点均值或颜色离散度扩展抠除范围。

### 6.4 基于采样背景色的 Despill

不设置固定的绿幕/蓝幕开关，也不只抑制采样色的主通道。系统将 Alpha
为 `a` 的半透明像素视为前景 `F` 与采样背景均值 `B` 的合成结果 `C`，并对
完整 RGB 向量执行颜色反混合：

```text
C = aF + (1 - a)B
F = clip((C - (1 - a)B) / max(a, 1/255), 0, 255)
result = lerp(C, F, despill_amount)
```

仅对 Alpha 字节处于 `1..254` 的像素计算恢复色。Alpha 为 `0` 或 `255` 时，
输出 RGB 必须与输入逐字节一致；`despill_amount = 0` 时整张图 RGB 不变；
`despill_amount = 1` 时半透明像素使用恢复色，中间值在原始合成色与恢复色
之间线性插值。

该模型没有 Trimap 或前景颜色先验，无法区分“接近采样背景色的真实前景”与
“背景颜色混入”。这类真实前景色可能发生偏移，用户可降低 Despill Amount
以换取更保守的颜色保留。

## 7. Matte 与预览

### 7.1 初始 Alpha

算法使用 Keylight 风格的主色通道覆盖率。设采样色的最强通道为 `D`，
`screen_balance` 为 `b`，先在其余两个通道之间计算平衡值，再比较主通道的
饱和度：

```text
screen_other = (1 - b) * max(screen_other_channels) + b * min(screen_other_channels)
screen_saturation = screen[D] - screen_other
pixel_other = (1 - b) * max(pixel_other_channels) + b * min(pixel_other_channels)
pixel_saturation = pixel[D] - pixel_other
coverage = clip(screen_gain * pixel_saturation / screen_saturation, 0, 1)
alpha = 1 - coverage
```

默认 `screen_gain = 1.00`、`screen_balance = 0.50`。提高 Screen Gain 会抠除
更多与幕布主色方向一致的像素；Screen Balance 决定两个非主通道对覆盖率的
相对贡献。结果保持连续 Alpha，以保留半透明边缘。

### 7.2 MVP 参数

| 参数 | 范围 | 默认值 | 作用 |
| --- | --- | --- | --- |
| Screen Gain | 0.00 - 2.00 | 1.00 | 调整主色覆盖率和抠除强度 |
| Screen Balance | 0.00 - 1.00 | 0.50 | 平衡两个非主色通道 |
| Clip Black | 0.00 - 1.00 | 0.00 | 将低 Alpha 压向透明 |
| Clip White | 0.00 - 1.00 | 1.00 | 将高 Alpha 压向不透明 |
| Shrink / Grow | -10 - 10 px | 0 | Alpha 收缩或扩张 |
| Feather | 0 - 10 px | 0 | Alpha 边缘羽化 |
| Despill Amount | 0.00 - 1.00 | 1.00 | 采样背景色反混合强度 |

每个参数同时提供同步的范围滑块和数值输入框：滑块用于快速调整，数值框用于
精确输入；两者共享同一数值、范围、步长和字段校验。

### 7.3 预览模式

- Final：透明棋盘格上的当前图片或当前视频帧 RGBA 结果。
- Alpha Matte：当前图片或当前视频帧中，黑色代表透明、白色代表不透明、灰色代表半透明。
- 视频时间轴按源帧率步进，显示当前时间/总时长、帧率、源尺寸和估算帧数。连续
  seek 使用 `100 ms` 防抖并遵循“最新请求获胜”；取样请求必须包含当前已渲染帧
  对应的后端解析时间戳。
- 实时参数预览要求媒体已加载、已有且仅有一个有效采样色，并且所有参数通过校验。
- 有效参数变化使用可替换的 `150 ms` 防抖计时器；Final / Alpha Matte 切换立即请求，
  不等待防抖。
- 预览请求不进入共享操作等待状态，不禁用表单、滑块或取样操作，允许快速调整产生
  并发请求。
- 预览以最新序列为准：过期成功不得替换预览，过期失败不得显示错误，过期收尾不得
  改变检查或取样操作的等待状态。
- 最新预览失败时保留上一次成功预览并显示错误。无效参数（包括
  `Clip Black >= Clip White`）显示现有字段校验，不发送预览请求。

预览可使用降采样图以控制响应时间；导出始终使用源分辨率。视频的一个 Screen
Color 与 Screen Gain、Screen Balance、Clip Black、Clip White、Shrink/Grow、
Feather、Despill Amount 七个静态参数应用于全部解码帧。

## 8. 输出

- 图片格式固定为 RGBA PNG；默认输出路径为 `<输入文件名>_keyed.png`，位于输入
  文件同级目录，用户可通过现有保存路径选择器指定输出文件。
- 视频按 FFmpeg 实际解码的完整时长和原始帧顺序输出，不抽帧、不补帧；目录名为
  `<输入文件名>_keyed_frames`，帧名从 1 开始按
  `<输入文件名>_keyed_%06d.png` 连续编号。
- 视频输出根目录可选；留空时使用输入视频同级目录。任务按实际处理帧数报告单调
  进度；已知估算总帧数时同时报告比例，结束事件使用实际帧数和最终目录。
- 每个视频序列包含 `manifest.json`，字段为 `version`、`source_path`、`width`、
  `height`、`fps`、`duration_seconds`、实际 `frame_count`、`pattern`、
  `screen_color`，以及包含全部七项静态值的 `params`。
- 视频先完整写入同一输出根目录中的临时目录，成功后以不覆盖方式原子发布最终
  目录；成功或失败均清理匹配的临时目录。
- 图片输出文件或视频最终目录若已存在，任务必须失败并提示用户更换位置，不得
  静默覆盖。

## 9. 验收标准

1. 用户可从本地路径导入 PNG/JPG/JPEG 图片或 FFmpeg 可解码的
   MOV/MP4/M4V/WebM/MKV/AVI 视频，错误路径、不支持后缀或解码失败有明确提示。
2. 用户在预览画布点击后，后端返回与原图对应坐标的 RGB/HEX 采样结果。
3. 系统始终只保留一个采样颜色；重新取样会替换当前颜色，清空后不可预览或导出，低饱和度颜色必须拒绝。
4. 对绿色和蓝色背景测试素材，背景区域基本透明，主体核心区域保持不透明。
5. 参数通过同步的滑块和数值框调整；有效变化在最后一次输入 `150 ms` 后请求预览，
   Final / Alpha Matte 切换立即请求，快速连续调整或 seek 只渲染最新响应。
6. 视频显示时间轴和元数据；当前帧取样携带所选时间戳，一个 Screen Color 和七个
   静态参数应用于全部视频帧。
7. 图片 PNG 与输入尺寸一致；视频按原始解码帧率完整导出连续命名、源尺寸 RGBA
   PNG 序列和字段完整的 `manifest.json`。
8. 图片文件和视频目录默认不覆盖；视频目录仅在全部内容完成后原子出现，且无匹配
   临时目录残留。
9. 视频任务显示单调逐帧进度、完成状态和最终输出目录。
10. 对白色前景叠加绿色背景的 25%、50%、75% Alpha 合成像素，默认
   `despill_amount = 1.0` 的 Despill
   可在 uint8 舍入误差内恢复白色；透明和不透明端点的 RGB 保持逐字节不变。
11. Despill 仅处理 Alpha 为 `1..254` 的像素；由于 MVP 没有 Trimap 或前景颜色
   先验，接近幕布色的真实前景可能偏色，用户可降低 Despill Amount。

## 10. 技术约束

- 前端：既有 React + Vite + TypeScript + Zustand。
- 后端：既有 FastAPI、SSE 任务日志和本机路径选择 API。
- 算法：Python、NumPy、OpenCV、Pillow；视频通过随应用分发的 FFmpeg 解码。
- 处理接口必须避免双重提交并复用现有任务状态和日志订阅机制。
- 视频 v1 不处理音频，不提供取消、入点/出点范围、批量抠像或参数关键帧。
