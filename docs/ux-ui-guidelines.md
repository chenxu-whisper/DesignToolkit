# DesignToolkit UX/UI 视觉规范


## 1. 规范层级

本文使用以下标记：

- **[基线] 当前强制基线**：当前产品已经采用的强制规则。新增模块不得破坏。
- **[推荐] 新增模块推荐标准**：新增模块应优先采用的设计标准。偏离时必须有明确的工作流理由。
- **[禁止]**：不得引入的模式。

运行时代码仍是最终事实来源：

- 颜色、间距、圆角、阴影和层级：`web/frontend/src/styles/tokens.css`
- 应用壳层：`web/frontend/src/styles/shell.css`
- 通用控件：`web/frontend/src/styles/controls.css`
- 模块专用布局：`web/frontend/src/styles/modules.css`
- 通用 React 组件：`web/frontend/src/components/`

规范与代码冲突时，不得默默选择其一。应先确认预期，再同步修改规范、实现和测试。

## 2. 产品体验方向

DesignToolkit 是面向重复操作和专业媒体处理的生产工具，不是营销站点。

### 2.1 体验原则

1. **任务优先**
   用户进入模块后，应立即看到输入、参数、预览或执行入口，不设置欢迎页和功能宣传区。

2. **安静、专业、工具导向**
   信息通过排版、间距、边界和语义状态组织。视觉效果不得抢占任务内容的注意力。

3. **紧凑但不拥挤**
   允许较高信息密度，但相关项必须分组，主次必须明确，控件尺寸不得因内容变化而跳动。

4. **状态可见且可恢复**
   加载、排队、运行、成功、失败、禁用和空状态必须明确。异步操作不得让用户猜测系统是否响应。

5. **桌面高效，移动可完成**
   桌面端服务高频操作；390px 移动视口仍必须可浏览、填写、提交和查看结果，不允许横向溢出。

6. **本地模式与托管模式保持同一心智模型**
   两种模式可以使用不同的文件输入方式，但字段含义、任务状态、错误处理和结果反馈应保持一致。

### 2.2 视觉性格

- 冷静的浅青灰中性色作为工作表面。
- 绿色作为稀缺的主强调色，仅用于主要操作、选中状态和键盘焦点。
- 信息、成功、警告和错误使用独立语义色。
- 浅色主题依靠边界与轻阴影表达层级；深色主题主要依靠表面亮度差表达层级。
- 技术数据、时间码和日志可使用等宽字体；其余界面保持统一无衬线字体。

## 3. 应用壳层与模块原型

### 3.1 共享应用壳层

**[基线]** 所有模块必须运行在同一应用壳层中：

- 顶部命令栏：品牌、当前模块上下文、任务状态、主题控制、日志控制。
- 桌面工具栏：模块导航。
- 主工作区：当前模块内容。
- 底部任务日志：可折叠、可调整高度，展示长任务的过程与耗时。

**[基线]** 桌面壳层尺寸：

| 区域 | 当前尺寸或约束 |
|---|---|
| 顶部命令栏 | `52px` |
| 桌面工具栏 | `72px` |
| 折叠日志栏 | `44px` |
| 展开日志栏最小高度 | `120px` |
| 展开日志栏最大高度 | 当前视口高度的 `45%` |
| 工作区默认内边距 | `24px` |

**[基线]** 小于等于 `759px` 时：

- 工具栏改为顶部横向滚动导航。
- 工作区内边距收紧为 `16px`。
- 品牌文字和模块长描述可隐藏，但模块名称与关键状态必须保留。
- 日志条目改为单列，避免横向滚动。

**[推荐]** 新增模块不得创建第二套全局导航、全局任务状态或独立日志面板。

### 3.2 模块页面原型

新增模块先选择最接近的页面原型，再决定局部结构。

#### A. 单任务表单

适用于转换、导出、批处理和参数较少的能力。

- **[基线]** 内容容器最大宽度 `960px`，居中显示。
- **[基线]** 表单最大宽度 `720px`。
- **[推荐]** 使用单列主流程；仅当字段天然成对且空间允许时使用两列。
- **[推荐]** 每个表单只有一个主要提交动作。
- **[推荐]** 成功结果或失败信息靠近模块标题和表单，不放到独立页面。

#### B. 媒体工作台

适用于画布预览、采样、时间轴、参数联动和反复调节。

- **[基线]** 预览或画布是第一视觉焦点。
- **[基线]** 参数检查器是次级区域，桌面可并排，窄屏改为抽屉或对话框。
- **[推荐]** 工具栏悬浮在画布内部时，只提供与当前画布直接相关的命令。
- **[推荐]** 时间轴、画布和参数必须保持稳定尺寸，动态状态不得推动整体布局。
- **[推荐]** 复杂参数通过分区和渐进披露组织，不把所有控制平铺在首屏。

#### C. 专业工具面板

仅在能力确实需要高密度、多模式或多工具协作时采用。

- **[推荐]** 优先使用图标、分段控制、滑块、步进器、菜单和标签页。
- **[推荐]** 每个模式保留稳定的区域尺寸和清晰的选中状态。
- **[推荐]** 提供键盘操作时，必须同时保留可发现的可视操作路径。
- **[禁止]** 为普通表单模块套用复杂编辑器结构。

## 4. 信息层级与布局

### 4.1 页面层级

每个模块按以下顺序组织：

1. 模块标题。
2. 当前结果、任务失败或模块级错误。
3. 核心工作区：表单、预览或编辑器。
4. 局部辅助状态与次级操作。
5. 全局任务进度和详细日志由共享壳层承载。

**[推荐]** 页面标题描述能力名称，不使用营销式价值主张。模块内部不重复解释应用已有功能。

### 4.2 间距

**[基线]** 采用 4px 基础网格：

| Token | 值 | 常见用途 |
|---|---:|---|
| `--space-1` | 4px | 紧密图标间隔、微调 |
| `--space-2` | 8px | 控件内部、同组元素 |
| `--space-3` | 12px | 字段、紧凑工具栏 |
| `--space-4` | 16px | 表单字段、移动工作区 |
| `--space-5` | 20px | 面板内容、模块区块 |
| `--space-6` | 24px | 桌面工作区、主要分组 |
| `--space-8` | 32px | 大区块分隔 |

**[推荐]**

- 同级元素优先使用 `gap`，不通过零散 margin 拼接布局。
- 局部光学校正可以使用小幅非 token 值，但必须有清晰原因。
- 组件应优先响应容器宽度；页面级结构才使用 viewport breakpoint。

### 4.3 卡片、边界与分组

- **[基线]** 圆角只使用 `4px`、`6px` 和 `8px` 三档。
- **[推荐]** 卡片仅用于真正独立、可操作或重复的对象。
- **[推荐]** 页面区块优先使用间距、排版和分隔线组织。
- **[禁止]** 卡片嵌套卡片。
- **[禁止]** 把每个页面区块都做成漂浮卡片。
- **[禁止]** 使用胶囊形面板、夸张圆角或装饰性边框。

### 4.4 阴影与层级

| Token | 用途 |
|---|---|
| `--shadow-sm` | 轻量面板、画布 |
| `--shadow-md` | 浮动工具栏 |
| `--shadow-lg` | 菜单、抽屉、对话框 |

**[基线]** 深色主题中普通阴影应减少或取消，改用表面亮度差表达层级。

## 5. 色彩与主题

### 5.1 使用原则

- **[基线]** 使用 OKLCH 和语义 token。
- **[基线]** 组件不得直接复制 `tokens.css` 中的颜色值。
- **[推荐]** 新增色值前先确认现有语义角色是否已覆盖。
- **[推荐]** 强调色保持稀缺，不用于大面积背景。
- **[禁止]** 仅通过颜色表达状态、错误或选中。
- **[禁止]** 渐变、玻璃拟态、装饰光斑、发光边框和无业务意义的背景图案。

### 5.2 表面

| Token | 用途 |
|---|---|
| `--surface-app` | 应用背景 |
| `--surface-panel` | 固定面板、表单、工具栏 |
| `--surface-raised` | 菜单、浮动控件、最高层表面 |
| `--surface-subtle` | 次级控件、禁用区、弱分组 |
| `--surface-input` | 输入控件 |
| `--surface-inverse` | 日志等反色技术区域 |
| `--surface-overlay` | 对话框遮罩 |

### 5.3 文本和边界

| Token | 用途 |
|---|---|
| `--text-primary` | 标题、主要内容 |
| `--text-secondary` | 标签、次级内容 |
| `--text-muted` | 元数据、占位符、辅助信息 |
| `--text-inverse` | 反色表面内容 |
| `--border-subtle` | 常规分隔 |
| `--border-strong` | 输入框、重要边界 |

### 5.4 语义色

| 语义 | Token | 使用场景 |
|---|---|---|
| 主强调 | `--accent*` | 主操作、选中、焦点 |
| 信息 | `--info*` | 排队、运行、普通提示 |
| 成功 | `--success*` | 完成、有效结果 |
| 警告 | `--warning*` | 可继续但需注意 |
| 危险 | `--danger*` | 校验失败、任务失败、破坏操作 |

**[推荐]** 正文和控件满足 WCAG 2.2 AA：普通文本至少 4.5:1，较大文本和图形控件至少 3:1。占位符也必须满足可读性要求。

## 6. 排版

### 6.1 字体

**[基线]** 主字体栈：

```css
Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif
```

**[基线]** 日志、时间码和技术数据使用：

```css
ui-monospace, SFMono-Regular, Consolas, "Liberation Mono", monospace
```

**[推荐]** 不为新增模块引入额外字体。数字列、进度、时间码和缩放比例使用 `font-variant-numeric: tabular-nums`。

### 6.2 字号层级

| 层级 | 当前基线 | 使用场景 |
|---|---:|---|
| 模块标题 | 20px / 760 | 页面唯一 H1 |
| 面板标题 | 14px / 700–750 | 检查器、分区 |
| 控件正文 | 13px / 400–760 | 按钮、选择、正文 |
| 字段标签 | 12px / 700 | 表单标签、分区名 |
| 元数据 | 11px | 时间码、媒体属性、日志 |
| 工具栏导航 | 10px | 仅限图标下的短标签 |

**[推荐]**

- 产品界面使用固定字号，不随 viewport 宽度连续缩放。
- 模块内不使用 hero 级字体。
- 禁止负字距，默认 `letter-spacing: 0`。
- 文字必须适应容器；优先换行、截断或调整布局，不缩成不可读的小字。

## 7. 通用组件

### 7.1 按钮

#### 主操作

- 使用 `.submit-button` 或后续统一主按钮组件。
- 每个独立工作流只有一个主要视觉重点。
- 标签使用“动词 + 对象”，如“开始导出”“生成预览”。
- 运行中或请求未完成时必须防止重复提交。

#### 次操作

- 使用 `.secondary-button` 或 `.secondary-action-button`。
- 适合打开检查器、应用非主要命令或进入次级流程。

#### 图标按钮

- 使用 `.icon-button` 和 Lucide 图标。
- 必须同时提供 `aria-label` 和 `title`；陌生图标应提供 tooltip。
- 视觉尺寸可为 32–36px，粗指针环境的点击区域必须至少 44×44px。
- 不使用手绘 SVG 替代已有 Lucide 图标。

#### 完整状态

每个可交互控件必须考虑：

1. Default
2. Hover
3. Focus-visible
4. Active
5. Disabled
6. Loading
7. Error
8. Success

不适用的状态可以省略，但必须是明确判断，而不是遗漏。

### 7.2 表单控件

- **[基线]** 每个输入都有可见 `<label>`，placeholder 不替代标签。
- **[基线]** 错误通过 `aria-invalid` 和 `aria-describedby` 关联到字段下方的错误文本。
- **[推荐]** 文本和路径使用输入框；选项集合使用 radio、checkbox、select 或菜单；数字使用 number、slider 或 stepper。
- **[推荐]** 字段变更时清除该字段的旧错误；提交时执行完整校验。
- **[推荐]** 路径输入在本地模式提供原生选择器，在托管模式提供上传；两者保持同一标签和结果语义。
- **[禁止]** 用普通文本按钮模拟 checkbox、toggle、色板或分段控制。
- **[禁止]** 在用户尚未完成输入时持续显示干扰性的错误。

### 7.3 菜单、抽屉和对话框

- 使用原生语义或可访问组件模式。
- 打开后焦点进入浮层；关闭后焦点回到触发器。
- 支持 Escape 关闭和合理的键盘方向键导航。
- 对话框外区域不可被误操作。
- 小于等于 `1179px` 的复杂参数检查器可以转为抽屉。
- 小于等于 `759px` 时抽屉可占满视口，并处理 safe-area inset。

### 7.4 状态、结果和错误

- 任务状态同时显示图标和文字。
- 运行状态允许动画，但必须响应 reduced motion。
- 成功结果显示明确输出或下载动作。
- 错误信息回答：发生了什么、可能原因、下一步如何处理。
- 不使用“出错了”“无效输入”等无法行动的文案。

## 8. UX 工作流

### 8.1 模块进入

- 用户切换模块后应直接进入可操作界面。
- 默认值应支持最常见路径，不要求先理解所有参数。
- 不创建营销式首屏、教程卡片墙或无操作价值的欢迎页。

### 8.2 输入与预览

- 输入提交、文件检查和预览请求应有清晰边界。
- 请求 pending 时，只禁用会造成冲突或数据竞争的操作。
- 允许安全地覆盖旧请求时，使用 latest-wins；陈旧响应不得覆盖新状态。
- 媒体预览必须保持稳定画布尺寸，加载状态不得造成布局跳动。

### 8.3 创建任务

- 创建请求期间阻止会卸载提交模块的导航。
- 任务 ID 注册完成后，可以恢复模块切换。
- 排队或运行中的任务通过共享状态和日志继续追踪，不将用户锁死在原模块。
- 提交按钮必须防止重复请求。

### 8.4 长任务

- 显示具体阶段，而不是只显示泛化 spinner。
- 有真实进度时显示进度；无法量化时显示当前动作。
- 详细过程进入共享日志面板，模块正文仅保留关键状态。
- 任务完成后提供结果位置或下载动作。

### 8.5 空、错、成状态

| 状态 | 要求 |
|---|---|
| 空状态 | 说明当前缺少什么，并指向一个明确动作 |
| 加载 | 描述正在加载的对象，避免只写“加载中” |
| 禁用 | 视觉降级且不可触发；必要时解释原因 |
| 错误 | 就近显示，保留可修改的输入，提供恢复路径 |
| 成功 | 简洁确认，突出结果或下一步 |

## 9. 响应式与输入方式

### 9.1 当前断点

| 条件 | 当前用途 |
|---|---|
| `max-width: 1179px` | 复杂检查器从并排面板变为抽屉 |
| `max-width: 759px` | 应用壳层、表单和时间轴改为移动结构 |
| `max-width: 479px` | 高密度采样列表重排 |
| `pointer: coarse` | 点击区域提升到至少 44px |

**[推荐]** 新断点由内容发生破坏的实际位置决定，不使用设备名称决定布局。

### 9.2 重排规则

- 两列表单在移动端变为单列。
- 桌面侧栏在移动端变为横向工具栏。
- 参数侧栏变为抽屉，不压缩媒体画布到不可用尺寸。
- 时间轴可以分为多行，但传输控制、当前时间和范围输入仍应可见。
- 固定格式控件使用 `minmax()`、`aspect-ratio`、明确轨道或容器查询保持稳定。
- 移动端、桌面端和中间宽度不得出现横向页面溢出。

### 9.3 安全区和缩放

- 全屏抽屉和底部操作区处理 `env(safe-area-inset-*)`。
- 不禁止浏览器缩放。
- 200% 浏览器缩放时，主要流程仍必须可完成。

## 10. 动效

- **[基线]** 微交互主要使用 `100–150ms`。
- **[基线]** 当前常规颜色和边界过渡为 `140ms ease-out`。
- **[推荐]** 只动画 `transform` 和 `opacity`；避免动画触发布局重排的属性。
- **[推荐]** 动效只用于反馈、空间关系和状态变化，不用于装饰。
- **[推荐]** 进入比离开稍慢，反馈动画不超过 500ms。
- **[基线]** 必须支持 `prefers-reduced-motion: reduce`。
- **[禁止]** 弹跳、漂浮、连续背景动画和大面积滚动入场。
- **[禁止]** 依赖 JavaScript 成功执行才能让核心内容从透明状态变为可见。

## 11. 可访问性

新增模块至少满足：

- 使用语义化 HTML：`main`、`section`、`nav`、`form`、`fieldset`、`dialog` 等。
- 页面只有一个明确 H1，标题层级连续。
- 所有控件有可访问名称。
- 图标装饰使用 `aria-hidden="true"`。
- icon-only 控件提供 `aria-label`。
- 当前导航使用 `aria-current`。
- 状态更新使用恰当的 `role="status"`、`aria-live` 或 `role="alert"`。
- 键盘焦点统一使用至少 2px 的可见 focus ring。
- 相关菜单、tab、radio group 支持方向键模式。
- 不将 hover 作为唯一操作路径。
- 粗指针环境目标至少 44×44px。
- 颜色不是信息的唯一载体。
- 对话框正确管理初始焦点、焦点约束和触发器回焦。

## 12. UX 文案

### 12.1 语气

- 专业、直接、平静。
- 成功状态简短。
- 错误状态具体、可行动，不责怪用户。
- 技术术语仅在目标用户确实需要时保留。

### 12.2 命名

- 按钮使用“动词 + 对象”：`开始导出`、`下载结果`、`清除采样点`。
- 不使用 `确定`、`提交`、`点击这里` 作为缺少上下文的命令。
- 同一概念始终使用同一术语。
- 不用可见文本解释快捷键、布局或明显的控件用途。

### 12.3 错误结构

错误文案应尽量包含：

1. 哪个对象失败。
2. 为什么失败或需要什么格式。
3. 用户可以采取的下一步。

示例：

- 推荐：`输出尺寸必须为“宽x高”，例如 1920x1080。`
- 禁止：`输入无效。`

## 13. 新增模块实现流程

1. **选择页面原型**
   明确属于单任务表单、媒体工作台还是专业工具面板。

2. **定义核心工作流**
   列出输入、预览或校验、任务创建、运行、结果和恢复路径。

3. **复用现有基础**
   优先使用共享壳层、任务状态、日志、表单控件、语义 token 和 Lucide 图标。

4. **定义状态模型**
   至少考虑 idle、pending、queued、running、succeeded、failed，以及陈旧响应和模块切换。

5. **设计响应式重排**
   先保证 390px 能完成流程，再优化桌面密度。复杂组件优先使用容器查询或稳定轨道。

6. **实现可访问交互**
   在组件首次实现时完成标签、键盘、焦点和状态播报，不留到最后补。

7. **补齐验证**
   覆盖组件测试、桌面/移动 E2E、主题、reduced motion 和无横向溢出。

### 13.1 抽象边界

满足以下任一条件时，才考虑提取共享组件或 token：

- 同一模式已出现三次或以上。
- 已明确有多个模块即将复用。
- 集中后能真正统一行为、可访问性或状态处理。

不要为单个模块的局部结构创建通用组件。共享组件必须有清晰 props、默认值、状态定义和使用说明。

## 14. 禁止项

新增模块不得：

- 创建独立于共享壳层的导航、任务状态或日志系统。
- 制作营销式 hero、功能宣传首屏或大面积装饰背景。
- 使用紫色渐变、玻璃拟态、光斑、发光和一色到底的配色。
- 在卡片中继续嵌套卡片。
- 使用大于 8px 的圆角作为常规产品界面风格。
- 为熟悉命令使用带文字的圆角按钮替代清晰图标。
- 自绘已有 Lucide 图标。
- 使用 viewport 宽度连续缩放产品界面字号。
- 使用负字距。
- 让文字、工具栏、画布、状态或浮层发生非预期重叠。
- 让 loading、错误文本或动态标签改变固定工具区域尺寸。
- 仅用颜色表达状态。
- 移除 focus outline 而不提供替代焦点样式。
- 在触摸设备上依赖 hover。
- 使用无恢复路径的笼统错误。
- 在没有复用证据时提前搭建完整组件库。

## 15. 验收清单

### 15.1 工作流

- [ ] 首屏直接提供核心操作，不是介绍页。
- [ ] 主任务路径从输入到结果完整可达。
- [ ] 异步状态明确，重复提交和陈旧响应受控。
- [ ] 错误后输入不会无故丢失，并有恢复路径。
- [ ] 长任务可通过共享状态与日志持续追踪。

### 15.2 视觉

- [ ] 仅使用既有语义 token 或已评审的新 token。
- [ ] 页面层级依靠排版、间距和边界，而非装饰。
- [ ] 每个工作流只有一个主要视觉操作。
- [ ] 圆角、阴影、图标和状态样式与现有模块一致。
- [ ] 没有卡片嵌套、渐变、玻璃、光斑或营销式构图。

### 15.3 组件与交互

- [ ] 控件具备适用的 default、hover、focus、active、disabled、loading、error 和 success 状态。
- [ ] 所有 icon-only 按钮有 `aria-label`、`title` 或 tooltip。
- [ ] 表单标签、错误关联和禁用语义正确。
- [ ] 动态内容不会造成布局跳动或控件尺寸变化。
- [ ] 对话框、菜单和复合控件可使用键盘完成操作。

### 15.4 响应式

- [ ] 桌面、平板和 390px 移动视口没有横向溢出。
- [ ] 触摸目标至少 44×44px。
- [ ] 参数面板、工具栏和时间轴在窄屏正确重排。
- [ ] 文本不会与相邻元素重叠或溢出容器。
- [ ] 200% 缩放下核心流程仍可完成。

### 15.5 主题、动效与可访问性

- [ ] 浅色、深色和跟随系统主题均可读。
- [ ] 文本、图标、边界和 focus ring 对比度满足要求。
- [ ] `prefers-reduced-motion` 下没有非必要位移动画。
- [ ] 状态不是只靠颜色表达。
- [ ] 屏幕阅读器可理解标题、字段、状态和操作。

### 15.6 工程验证

- [ ] Vitest 组件和状态测试通过。
- [ ] Playwright 桌面与移动关键流程通过。
- [ ] TypeScript 检查和生产构建通过。
- [ ] 浏览器控制台没有新增错误。
- [ ] 新模块没有引入未说明的独立视觉系统。

## 16. 维护规则

- 新增或调整 token 时，同步更新本文档和主题值。
- 新增共享组件时，记录用途、变体、状态和反例。
- 评审新增模块时，先检查工作流和信息层级，再检查视觉细节。
- 现有模块与推荐标准不一致时，不进行无关的大规模重构；在相关功能迭代中逐步统一。
- 对规范的例外必须说明业务原因、影响范围和测试方式。
